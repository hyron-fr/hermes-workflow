Artefacts de l'interface de décision humaine (#5)

PROTOTYPE RATIFIÉ PAGE INERTE — 0 composant interactif

Cette page matérialise les artefacts déjà ratifiés par t3 — un diagramme de séquence V2 et une maquette de texte inerte en 2 messages. Elle n'en produit aucun nouveau : l'humain juge ici un rendu versionné et rejouable, là où un artefact posté dans Discord n'est ni l'un ni l'autre. Les empreintes sont reproduites par issue-5-decision-flow.measure.py, le script de mesure voisin : si un artefact rendu dérive de ce que la page déclare, le banc sort en erreur en le nommant.

Aucun bouton, aucune action, aucun composant : Discord notifie, il ne décide pas — la décision se prend par un commentaire GitHub commençant par /ok.

Le flux en 3 phases

  1. 1. Création automatique — au premier blocage d'une carte — L'escalade crée une issue enfant pour cette carte (0 LLM) et y pose le « point à statuer ».
  2. 2. Décision — un commentaire GitHub commençant par /ok — Discord notifie avec le lien direct vers le point à statuer ; la décision est un commentaire GitHub commençant par `/ok`. Tout autre commentaire est une demande d'éclaircissement : la carte reste bloquée.
  3. 3. Re-blocage — la même issue enfant est rouverte — Si la carte re-bloque sur le même sujet, la même issue enfant est rouverte : jamais une 2ᵉ enfant pour une même carte, un nouveau `/ok` requis.

Le rendu du flux utilise le mermaid.min.js déjà versionné dans le dépôt (bridge/mermaid.min.js) : aucun CDN, aucune requête réseau.
