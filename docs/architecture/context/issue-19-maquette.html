Issue #19 — « Discord thread title and description update » : maquette du contrat

Artefact inerte à valider au gate humain avant toute slice de production. Aucun JavaScript, aucun asset externe, aucune requête réseau : les vignettes sont des copies statiques de l'interface Discord (thème sombre), construites à partir du format arbitré par l'humain le 02/10/2026 (Q1 = 1a, Q2 = 2b, Q3 = d).

1. Le titre du thread dans la liste des threads (4 états)

Format arbitré : <icône> <repo>|#<numéro d'issue>|<titre de l'issue> — l'icône est en tête, l'identité est repo + numéro d'issue GitHub, et le titre vient de l'issue (jamais de la carte kanban). Les quatre états portent la même identité : seule l'icône change.

Contrainte mesuréeValeurConséquence sur le format
Longueur maximale d'un nom de thread (Discord) 1–100 caractères le préfixe 🎬 hermes-workflow|#19| fait 22 car. (23 avec ⚙️, 2 points de code) → 78 caractères de titre ; le titre actuel (43) donne un nom de 65 → aucune troncature aujourd'hui.
Ce qui est tronqué si le titre est trop long jamais le préfixe repo, | et numéro d'issue sont coupés en dernier : un nom tronqué casserait la résolution du thread si l'identité était coupée.
Renommages acceptés par Discord 3ᵉ PATCH name = 429, retry_after ≈ 600 s un seul écrivain du titre (le keeper), coalescé : ≥ 1 renommage par fenêtre ≥ 10 min, priorité ⚠ > 🛑 > ⚙️ > 🎬.

2. Le bloc « Description » épinglé (message dédié, épinglé)

Un thread Discord n'a aucun champ description (PATCH {"topic": …} → 200 puis topic = None, mesuré : la valeur est jetée en silence). Le contrat arbitré est donc un message dédié épinglé ; le message d'accueil reste intact. Une ligne non résolue est omise — jamais de placeholder.

Le nom du thread est lu par le pipeline (escalade d'une carte bloquée, boutons de décision). Changer le format sans élargir les lecteurs fait retomber silencieusement l'escalade dans le canal.
